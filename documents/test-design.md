# Forge 验收设计

本文将[需求](requirements.md)映射为可执行、可取证的验收场景。覆盖原生 Bazel、CMake、CMake/Conan、原生消费者及交付制品，具体操作入口见[测试说明](../tests/README.md)。

本机 Linux/amd64 镜像、`forge-bazel` 和 `forge-shell` 已提供本地入口；`examples/check.py` 的 01–04 Debug/Release 八次原生运行、TC-ENV-01/local、TC-ENV-02/local、TC-DEP-05/local 已在容器中通过。独立入口测试还覆盖部分本地镜像/状态拒绝行为。新增官方环境与入口用例 TC-ENV-05 至 TC-ENV-07、TC-ENTRY-01 至 TC-ENTRY-05、TC-CI-03 尚未作为完整用例注册到 runner；已有用例涉及镜像身份或入口的扩展断言也未因此自动通过。以下是验收规格，不是 CI、ARM64 原生、目标运行或远程发布的 PASS 报告。

## 1 判定与执行范围

测试区分配置分析、编译链接、ELF/布局检查、部署运行和跨机复用。前一层成功不能代替后一层证据。

| 状态 | 含义 |
| --- | --- |
| PASS | 对明确范围的全部行为断言通过 |
| FAIL | 退出码、诊断、制品或行为不符合预期 |
| SKIP | 该范围不适用于所选平台 |
| BLOCKED | 环境或外部执行/取证前置条件不具备 |

负向配置用例要求明确的失败诊断，正常运行要求退出零。Sanitizer 用例要求真实错误、预期报告和非零退出，独立无错误对照必须成功。未执行不计为通过。

TC 编号对应验收目标，scope 对应具体执行环境或局部验证。一个 TC 的本机 scope 通过，不表示它的目标运行或跨机 scope 已通过。runner 的用例登记和测试设计本身都不是执行结果。

## 2 环境与夹具

| 环境 | 要求 | 用途 |
| --- | --- | --- |
| E-HX、E-HA | 满足支持矩阵的干净 Linux x86_64、ARM64 宿主，仅准备入口基础依赖、Docker 和源码，不预装项目工具/SDK | 官方镜像获取、架构选择及入口验收 |
| E-X1、E-X2 | 两台独立 x86_64 宿主内的官方构建容器，相同平台镜像与工具/SDK 身份，不共享工作区、output base、磁盘缓存和 Conan home | x86_64 原生、ARM64 交叉、独立缓存复用 |
| E-A1 | 使用锁定 ARM64 平台镜像的官方构建容器 | ARM64 原生与交叉部署配置 |
| E-TX、E-TA | 匹配目标 ABI/SDK 的干净 x86_64、ARM64 运行环境 | 安装、加载、插件、调试和插桩执行 |
| E-RC | 独立命名空间的远程缓存，不配置远程执行器 | 命中、失效与本机回退 |
| E-CONAN | 可控配方、源码和二进制的 Conan 来源 | 精确预编译、缺包、修订变化和失败注入 |

目标执行环境由 CI 提供。环境不得预装夹具的业务私有库来掩盖缺失闭包。SDK 运行库与编译时目标头文件/链接库必须匹配，不能只校验加载器路径。

构建容器不代替干净目标环境。当前本地环境只覆盖 linux/amd64 镜像，没有 E-HA/E-A1 的 ARM64 原生环境、匹配 `/opt/eros` SDK、目标设备或 E-X1/E-X2 独立机器条件。两套同宿主容器可以验证入口隔离，但不能冒充独立机器缓存证据。记录支持的 Docker 版本/模式、内核、执行架构和安全策略；缺少所需构建执行平台或匹配 SDK 时，受影响 scope 保持 BLOCKED。仿真运行另一架构的构建镜像不自动扩展支持矩阵；目标运行 scope 则可由 CI 按 D17 使用匹配目标 CPU/ABI/SDK 的模拟器，须记录能力和限制，不外推为真实设备验收。

| 夹具 | 观察对象 |
| --- | --- |
| F-BASIC | 三条构建路径的等价计算、程序、库和生成头文件 |
| F-LINK | `app -> foo -> bar` 的真实外部符号，静态/共享/PIC 原生消费者 |
| F-CONAN | 小型源码包、patch、配置生成、传递依赖、host/build 上下文 |
| F-RUNTIME | 多层共享库、SONAME 链、插件、插件依赖和唯一资源标记 |
| F-VERSIONS | 两个包的独立私有版本，使用独立进程 |
| F-DEBUG | 业务、CMake、第三方函数的源码定位和受控崩溃 |
| F-SAN | 业务与第三方编译单元内的运行时错误，以及无错/同步对照 |
| F-FAIL | 缺输出、缺锁、坏摘要、路径冲突和架构矛盾 |
| F-ENTRY（待实现） | 明确的 build/test/run/query 目标，记录 argv、cwd、stdin/stdout/stderr、TTY、环境、退出码及信号/子进程；含独立消费工作区与 Repo/Git 元数据布局 |

夹具应小到能真实源码编译，不能用空包或纯头文件替代所有依赖获取场景。测试夹具验证规则，不充当面向入门者的教学工程；教学内容见[入门示例](../examples/README.md)，扩展路线见[示例规划](examples-plan.md)。

## 3 覆盖矩阵

| 维度 | 覆盖 |
| --- | --- |
| 环境交付 | 两种执行架构的平台摘要、开发/CI 一致、不可用与身份错误、受控升级 |
| 调用入口 | 宿主 Bazel 与容器内直接调用、启动选项、交互/非交互、标准流与信号 |
| 状态与权限 | 服务端复用、工作区/环境/实例隔离、UID/GID、挂载路径、清理与沙箱 |
| 路径 | 原生 Bazel、`cmake_forge`、`cmake_conan_forge` |
| 平台 | 四种预设，在兼容执行环境中验证 |
| 模式 | Debug、Release，切换时不清空缓存 |
| Sanitizer | none、ASan、UBSan、TSan、ASan+UBSan、关闭及非法组合 |
| 符号 | 开/关，Release 保持优化，覆盖第三方源码 |
| 依赖 | 精确二进制、源码回退、不匹配变体、获取/构建失败 |
| 链接 | 静态、动态、PIC、同一逻辑库的形式选择 |
| 缓存 | 冷缓存、本机、独立机器、输入失效、快照迁移 |
| 交付 | 运行布局、私有 deb、真实多配置、测试包、符号包 |

基础构建覆盖三条路径、四个平台和两种模式。其余场景使用代表性组合；工具链、SDK、profile 或 sanitizer 变更扩大到所有受影响范围。P0 是能力发布的必要门槛，P1 用于完整回归。

## 5 证据要求

环境记录包含实际运行的平台镜像摘要及其发布清单、工具环境/SDK 身份与缺失状态、执行架构、Docker 版本/模式、宿主内核、沙箱与额外权限配置。实际摘要须核验运行实例，不能仅保存请求的标签或用户填写的字符串；日志中不记录凭据。

入口等价性记录实际 argv、cwd、有效 rc/受控环境、标准流、退出码和相应构建行为，不仅比较最终文件存在。服务端复用记录容器与 Bazel 服务端身份；并发隔离记录 output base、输出链接和报告位置。一次快速重建不能独立证明服务端复用或远程缓存命中。

跨机缓存必须记录服务端命中及 action 执行信息，区分本机 action cache、磁盘缓存和远程命中。E-X2 不共享 E-X1 的 output tree 或 Conan home。若获取阶段有独立缓存策略，必须单独说明，不能掩盖编译未命中。

运行闭包验证须真实调用插件并使用唯一资源标记；只看到 dlopen 成功不足以证明依赖完整。不同版本共存分别启动独立进程。

调试验证使用发布二进制、归档符号和源码映射做实际 GDB 定位，并验证故意错配。仅有 `-g`、`.debug_*` 节或 `not stripped` 不构成通过。

Sanitizer 错误须位于实际第三方编译单元，不能以内联到消费者的代码冒充第三方插桩。ASan/UBSan 分开触发；TSan 最多尝试三个独立调度，退出零仅表示未检测到，必须取得真正的非零竞态报告。异常崩溃/错误诊断不能靠重试掩盖。同步/无错对照单独成功。

原生 ARM64 与交叉 ARM64 两分支可证明配置、解释器和输出隔离，不替代 x86_64/ARM64 两 CPU 验收。必须检查依赖图和解包 ELF，不能只数 deb 文件。

源码以内容摘要审计。用户 Conan 缓存按路径、大小、权限、mtime、ctime 和链接做元数据快照，每次审计有 30 秒期限，不完整扫描时报告 BLOCKED；不对整个用户缓存做无界内容哈希。并发/中断能力仍需要独立场景取证。

## 6 执行报告

验收 runner 支持 `--list`、`--all`、重复 `--tc` 和 scope 过滤；这些不是宿主 Bazel 入口的新参数。每项开始/完成都保存报告，`active_scope`、`run_complete`、预期与已记录数量区分完整运行和中断。`--strict` 将 SKIP/BLOCKED 引起的不完整选定范围返回为非零。

完整验收报告应记录源码提交及未提交内容摘要、锁摘要、实际平台镜像摘要、发布基线、环境/SDK 身份、配置、命令、退出码、日志、制品和符号关系。本地入口已在宿主检查本机镜像 ID；runner 将入口注入的 ID 标为**调用者声明**，并与 Bazel 环境清单核对其环境摘要。声明存在而清单采集/匹配失败时不运行选定用例，保存失败证据并返回非零；仅靠 runner 不能独立证明 registry 平台摘要。外部 scope 需要对应执行环境及实际取证接入，不能只修改状态标记就宣称通过。

每次验收 runner 调用有独立 output base，并检查子 Bazel 调用继承隔离设置；普通开发入口则验证其稳定实例的服务端复用。执行者检查字节和 inode 余量、约束并行度、归档必要记录并回收明确归属的缓存。Bazel `shutdown` 不删除 output base，目录保留不能无界累积。

目标官方门禁选择明确适用的 scope，使用 `--strict` 并核对完整报告。当前部分外部 scope 是 BLOCKED 占位，本地镜像不等于接通执行；它们必须完成实际取证后才能改为 PASS。对尚未接入的新用例记录未实现/未执行状态，不能隐藏它们并宣称完整能力验收通过。缺少 SDK 不豁免目标发布要求。
